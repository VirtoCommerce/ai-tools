VCST-6011: Designer actions menu no longer depends on clipboard permission

Page Builder Designer on vcptcore-qa, 2026-10-01. The section and page menus open populated in Firefox and in Edge without clipboard access, and a Shared Component can be created from the Designer.

Platform 3.1072.0PageBuilderModule 3.1030.0-pr-165-1ab4PR vc-module-pagebuilder#165 @ 1ab4e68 (open)Env vcptcore-qa · store B2B-store

Bug and root cause

getSectionsActions and getPageActions awaited hasClipboardData(), which calls navigator.clipboard.readText(). Without permission that promise never settles, so the menu stayed an empty overlay, and the menu was the only way to reach "Save selected as Shared Component". PR #165 removes the clipboard read from the menu build; the clipboard is read only when Paste is clicked.

Notes for the developer

  • Paste is never disabled. It stays enabled in prompt and denied states. In Firefox a Paste click waited more than 10 s with no paste and no manual-paste dialog; in Edge with permission blocked, a click only logs NotAllowedError. The silent wait has moved from opening the menu to clicking Paste. Needs one manual check in desktop Firefox.
  • Firefox right-click. Under Playwright the context menu opens on mousedown and the same press's mouseup/auxclick closes it 8–13 ms later. Real Windows Firefox may differ; macOS and Linux fire contextmenu on mousedown. The tune button works.
  • Low confidence. Pasting a copied Features section was refused with "Template Pages cannot contain section features", while Add block accepted the same type on that page (Edge, once).
