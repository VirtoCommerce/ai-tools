VCST-6152 · Wishlist share targets: one order, position-independent legacy sharedWithId

VERIFIED
env vcptcore-qaPlatform 3.1076.0XCart 3.1038.0-pr-141-b404Cart 3.1011.0-pr-194-8331SalesRep 3.1012.0-pr-21-8964PR vc-module-x-cart#141 (fix commit cd42696)2026-10-06

Bug and root cause

A write (createWishlist / changeWishlist) returned share targets in insertion order. Every later wishlist(listId) read returned them newest first. The deprecated sharedWithId means the first target, so it named a different org depending on which response the client kept. GetLegacyTargetDeltas treated only the first target as a no-op, so re-sending the value from the client's own save was refused with INVALID_OPERATION.

Fix: WishlistType orders targets by org id on every surface, and the legacy rule treats any present target as a no-op.
