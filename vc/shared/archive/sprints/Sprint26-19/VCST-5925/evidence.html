Bug and root cause

The deprecated sharingSetting.sharedWithId means "the first target". A write response listed targets in insertion order, a later read listed them newest first, so sharedWithId named a different org depending on which response the client kept. GetLegacyTargetDeltas treated only the first target as a no-op, so re-sending a present non-first id was refused with INVALID_OPERATION. The fix sorts targets by id on every surface and accepts any id already on the list.
