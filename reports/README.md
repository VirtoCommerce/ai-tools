# Reports — Naming Conventions & Structure

**The policy is normative, this file is a map.** Categories, size caps, required sections and
retention: [`.claude/rules/reports.md`](../.claude/rules/reports.md) (stub) →
[`.claude/knowledge/execution/reports-policy.md`](../.claude/knowledge/execution/reports-policy.md).
Anything that is not one of the policy's categories is **not a report file** — investigation logs,
progress notes and drafts go in a message, never on disk.

```
reports/
├── bugs/                      # Bug reports & evidence (policy §1 / §1a)
│   ├── open/                  # Active bugs — foldered by the severity DECLARED IN THE REPORT
│   │   ├── critical-high/     #   Critical/P0 + High/P1
│   │   ├── medium/            #   Medium/P2
│   │   └── low/               #   Low/P3  (a straddling grade files at the LOWER bucket)
│   ├── fixed/                 # Verified fixes — FLAT; /qa-verify-fix MOVES a file here (never both)
│   ├── closed/ · rejected/    # Closed / won't fix, false positive, cannot reproduce — flat
│   └── screenshots/           # Bug evidence screenshots — local only (images are gitignored, policy §9)
├── regression/                # Regression run outputs — gitignored except the two JSON files below
│   ├── REG-YYYY-MM-DD-HHMM/   # One consolidated run directory per run
│   ├── history.json           # Run history (90-day window)
│   └── test-run-status.json   # Current run tracking
├── monitoring/                # MONITOR-YYYY-MM-DD-HHMM/ — one per /qa-monitoring run
├── tickets/                   # Ticket run folders — GITIGNORED, local only, never committed
│   ├── SprintXX-YY/           # Default when a sprint folder exists (Sprint-current, else the newest)
│   │   └── VCST-XXXX/
│   │       └── <env>/                     # one folder per ticket AND env (vcst, vcptcore_dev, …)
│   │           ├── summary.json           # /qa-test's machine record
│   │           ├── test-strategy.md       # /vc-test:qa-test-strategy — one ## Round N per round
│   │           ├── test-model.md          # the Test Model (FULL path)
│   │           ├── testing-checklist.md   # the executed checklist (the FAST path's only durable record)
│   │           ├── verdict.md · triage-report.md · design-report.md
│   │           ├── verification-report.md # /qa-verify-fix (+ verification-summary.json, evidence.html)
│   │           ├── bugs/<severity>/       # the run's bug drafts
│   │           ├── exploratory/           # the run's SBTM session reports
│   │           ├── knowledge/             # domain/mind maps and API snapshots the run built
│   │           └── screenshots/
│   └── VCST-XXXX/<env>/       # When the repo has no sprint folder yet
├── ba/                        # BA deliverables, optionally in a domain subfolder ("Configurable products/", …)
│   ├── test-models/           #   older Test Models — new ones land in the run folder as test-model.md
│   └── release-notes/         #   per-ticket per-layer fragments + per-release aggregates
├── knowledge/                 # BL-AUDIT-YYYY-MM-DD.md — one receipt per /qa-review-bl run
├── exploratory/               # SBTM-*.md — one per /qa-sbtm or /qa-exploratory charter
├── coverage/                  # COV-YYYY-MM-DD-HHMM/ — one per /qa-coverage-gap run
├── performance/               # {topic}-investigation-<date>.md — /qa-perf-measure findings
├── fixes/                     # FIX-YYYY-MM-DD-HHMM/ — /qa-fix run records — gitignored, local only
├── graphql-fixtures-validation.md  # generated by the GraphQL fixtures validator (into the run folder when one is bound)
└── README.md                  # This file
```

**Where a ticket run writes.** `QA_OUTPUT_DIR` in `.env.local` can move the whole run folder out of the repo;
unset, it is `reports/tickets/<Sprint>/<TICKET>/<env>/`. Bind it with `npm run run:use -- <TICKET> [<env>]`.
Full layout and rules: [`.claude/knowledge/execution/run-output.md`](../.claude/knowledge/execution/run-output.md).
Run folders are not committed — the durable copy of a result is the tracker comment and its attachments.

Two separation rules: **raw browser output** (HAR, videos, console dumps) goes in `test-results/`
(gitignored), never here — and **never create `reports/<TICKET>/` at the repo root**; a ticket folder
is always under `reports/tickets/`. A `/qa-test-lifecycle` run summary is terminal-only — no file.

## Naming Conventions

| Type | Pattern | Example |
|------|---------|---------|
| Bug report | `bugs/open/<severity>/BUG-{Short-Description}.md` | `bugs/open/medium/BUG-Checkout-Payment-Overlap-iOS.md` |
| Bug with JIRA ref | `bugs/open/<severity>/BUG-{Description}-VCST-XXXX.md` | `BUG-Search-Clear-Button-Not-Restoring-Results-VCST-4499.md` |
| Full regression run | `regression/REG-YYYY-MM-DD-HHMM/` | `REG-2026-10-08-1119/` |
| Monitoring run | `monitoring/MONITOR-YYYY-MM-DD-HHMM/` | `MONITOR-2026-09-07-1448/` |
| Ticket run folder | `tickets/SprintXX-YY/VCST-XXXX/<env>/` | `tickets/Sprint26-22/VCST-6597/vcst/` — local only |
| Ticket run folder (no sprint folder) | `tickets/VCST-XXXX/<env>/` | `tickets/VCST-6314/vcptcore_dev/` — local only |
| Test Model | `<run folder>/test-model.md` (older ones: `ba/test-models/<TICKET>-<date>.md`) | `VCST-6077-2026-10-07.md` |
| Ticket document · release aggregate (`/qa-docs`) | `ba/<Domain>/<ticket>-<slug>-guide.md` · `ba/release-notes/release-<label>.md` | — |
| BA report | `ba/[<domain>/]{topic}-YYYY-MM-DD.md` | `ba-report-2026-03-04.md` |
| BL audit report | `knowledge/BL-AUDIT-YYYY-MM-DD.md` | `BL-AUDIT-2026-07-22.md` |
| Exploratory session | `exploratory/SBTM-{charter}-YYYY-MM-DD.md` (a ticket run's: `<run folder>/exploratory/`) | `SBTM-VCST-6077-2026-10-07.md` |
| Coverage generation run | `coverage/COV-YYYY-MM-DD-HHMM/` | `COV-2026-03-23-1600/` with coverage-generation-report.md |
| Performance report | `performance/{topic}-investigation-YYYY-MM-DD.md` | — |
| Auto-fix run | `fixes/FIX-YYYY-MM-DD-HHMM/` (local only) | `FIX-2026-10-06-0739/` |
| Test lifecycle run | Terminal-only chat summary, no file | Labeled `TLC-2026-03-23-1500` in the response |

## Rules

- All bug reports **must** use the `BUG-` prefix; the severity folder mirrors the severity the report declares
- Bug lifecycle: `open/<severity>/` → (verified fix, a **move**) → `fixed/` | (false positive / won't fix) → `rejected/`
- Readers walk `open/` **recursively** (`open/**/*.md`) — a flat scan misses every bug
- Screenshots go in the nearest `screenshots/` directory (bug or ticket) and are never committed; a UI claim in a tracker comment carries them inline
- Never `git add -f` anything under `tickets/` or `fixes/` — they are gitignored on purpose
- Retention: ephemeral run folders are pruned by `npm run reports:prune`; `bugs/`, `ba/`, `knowledge/` and `exploratory/` never prune (policy §9)
