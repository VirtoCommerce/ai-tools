## Part 0 — VALUE CHAIN

Value chain: **L1** admin starts Build / Delete and build / per-product Build index (or the recurring IndexChangesJob fires) → **L2** a job
is enqueued and a notification is returned → **L3** the job acquires the cluster-wide `IndexationJob` lock (or loses it) → **L4** the
provider index is written (blue-green swap on Delete and build) → **L5** the notification is sealed with a truthful result and the lock is
released → **L6** storefront/xAPI search reads the fresh index.

```mermaid

  T[L1 trigger: Build / Delete+Build / doc build / recurring] --> E[L2 enqueue + notification]
  E --> L{L3 TryExecuteAsync IndexationJob}
  L -- acquired --> W[L4 index documents under lockToken]
  L -- held by another run --> S[skip: notification error 'already in progress' + Error log]
  L -- lock store throws --> X[notification error + sealed + job FAILED]
  W -- ok --> F[L5 seal 'completed successfully' + release lock]
  W -- provider error --> FE[L5 seal 'completed with errors' + release lock]
  W -- cancel / lock lost --> FC[L5 seal 'canceled' + release lock]
  F --> R[L6 search reads fresh index]
  S --> N[next run must acquire]
  F --> N
  FE --> N
  FC --> N
```
