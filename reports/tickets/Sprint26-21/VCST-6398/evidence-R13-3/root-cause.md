# Root cause — R13-3

1. **Symptom:** after a full-page load of `/account/quotes`, headers show `quotes.quote_number_label`, `quotes.date_label`, `quotes.status_label`, `quotes.total_label` and the tab title "QA & quotes.meta.title"; `/account/quotes/{id}` shows "QA & quote_details.title". In-app navigation renders correctly.
2. **Lowest failing layer:** storefront, quotes module. The H1 and search placeholder (template `$t`) are translated in the same render; only strings evaluated once in setup are raw. GraphQL 200, rows rendered.
3. **Claim → evidence:**
   - (a) Locale load not awaited: `client-app/modules/quotes/index.ts:81` `void loadModuleLocale(i18n, "quotes")` in a sync `init()`. Deployed `index-u-TS9qWy.js` calls it without `await` in all 11 module inits; the app runner awaits federated modules and `router.isReady()` before mount, but not module locales.
   - (b) Setup-time capture: `quotes.vue` `usePageHead({ title: t("quotes.meta.title") })` and `const columns = ref([{ title: t("quotes.quote_number_label") }, …])`; `view-quote.vue:116-117`, `edit-quote.vue:198-199` `usePageHead({ title: t("quote_details.title", [quote.value?.number]) })`. Same in deployed `quotes-D0D84Rce.js`.
   - (c) Race: 7/7 FAIL when the page chunk beats the locale 304; 3/3 PASS otherwise (`network/locale-vs-page-chunk-timing.txt`).
4. **One sentence:** the quotes module starts its locale load without waiting, and the quotes pages read `t()` once in setup into non-reactive values, so when the page mounts first the raw keys are frozen.
5. **Ruled out:** by design (VirtoOZ StorefrontUserGuide "Quote Requests" shows a translated list); data drift (keys exist in the locale chunk; SPA renders them); random flakiness (follows cache state 10/10); console errors/404 (none).
6. **Regression archaeology (vc-frontend-next's own source):** `app-runner.ts:266` `void initModuleQuotes(router, i18n)`, `quotes/index.ts:81`, `quotes.vue:160-192`, `view-quote.vue:117`, `utils.ts:10-19` are byte-identical on vc-frontend-next `dev` (50019f0f) and PR #11 head d67b0e0a; the PR's `app-runner.ts` diff (initPunchout, domAnalyticsPlugin, federation conditionContext) does not change locale-vs-mount order. Last change to `quotes/index.ts`: 770291c1 (2026-02-19). Not introduced by this merge. No pre-merge vc-frontend-next build was observed live; KB-429A791E's 2.60.0-alpha.2579 sighting is not counted (theme repo unknown). Upstream vc-frontend 2.60.0 has identical lines.
7. **Confidence:** HIGH (DOM split, deployed bundle, source, HAR timing agree).
8. **Fix routing:** frontend, **VirtoCommerce/vc-frontend-next** (files above, at PR #11 head d67b0e0a); upstream VirtoCommerce/vc-frontend has the same defect and could take a matching fix. Fix-forward: await the module locale before routes mount, or make `columns` a `computed` and give `usePageHead` a getter title. The same unawaited `loadModuleLocale` is in the other 10 modules (may explain KB-F1071A5D, unverified). Related: detail/edit tab titles read "Quote request #" with no number even when translated, because `quote.value` is empty at setup.
