## Why GREEN is not testable

1. Out of the box, localhost returns **404 Page not found** on `/company/customer-orders`, and the sidebar has no Sales Rep hub. The local nginx generated by `qa-local-env provision.ps1 -Mode frontend` proxies `/graphql`, `/connect/token`, `/files`, `/api/files`, `/cms-content`, `/hub/` and `/revoke/token`, but not `/modules/`, so `mf-manifest.json` returns 404 (KB-847622A8).
2. To diagnose this, I temporarily added `location ^~ /modules/ { proxy_pass <platform>; }` and reloaded nginx. The hub came back. Network then showed `customer-orders-DWRY-_R8.js` loading from the **plugin** path. The theme's own `/assets/customer-orders-BEaHXPfP.js` was never requested.
3. Bundle diff: the theme chunk `customer-orders-BEaHXPfP.js` contains `"value-field":"id"` (the PR #2609 change). The plugin chunk `customer-orders-DWRY-_R8.js` does not.
4. I ran the STR once with the plugin loaded. The result matched RED (see table). I restored the original nginx config afterwards (`/modules` returns 404 again). The harness is as it was handed over.

**Conclusion:** a change under vc-frontend `client-app/modules/sales-rep` reaches the hub only through a **rebuilt SalesRep module storefront plugin** (or a theme with the built-in hub enabled). A theme-only PR artifact does not deliver it.

## Side findings

- **Harness gap (repo):** `.claude/skills/qa-local-env/provision.ps1` `-Mode frontend` omits a `/modules/` → platform location. Every Module Federation plugin hub returns 404 on a local frontend-only stand. Note: the location must be `^~ /modules/`, otherwise the `\.(json|js|css)$` regex location catches the manifest first.
- **Brief inaccuracy:** the pre-fix storefront is `vcptcore-qa-storefront.govirto.com`. `vcptcore-qa.govirto.com` is the platform/Admin SPA.

## To unblock

Verify on a stand where the SalesRep module carries a plugin rebuilt from PR #2609 (a vc-module-sales-rep PR/alpha that includes the vc-frontend change). Alternatively, use the theme with `sales_rep_builtin_enabled=true` and federation disabled, if that configuration is supported, so that the theme's own chunk renders.
