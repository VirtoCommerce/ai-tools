VCST-6010 · bug fix verification

Shared Component create now rejects unknown stores

VERIFIED WITH NOTES
env vcst-qamodule PageBuilderModule 3.1033.0-pr-170-236eplatform 3.1076.0PR vc-module-pagebuilder #170 @ 236e647date 2026-10-08

The bug and the fix

POST /api/page-builder-shared-components saved a component for any storeId, including one that does not exist. The result was a record that no store's library, page or workspace could reach.

The fix looks the store up through IStoreService after the store-scope permission check and before saving. A missing store now gets 400 Store '<id>' does not exist. and nothing is written.

A store-scoped user who names a store outside their scope gets 403 whether or not that store exists, so the 400 never tells them which stores are real.

Note. A store id that differs only in case (b2b-store) is accepted with 201 and saved exactly as sent. It is not an orphan: the lookup, search and permission check all ignore case, so the component appears in B2B-store's library and the store's own users can open and rename it. The only effect is a non-canonical store id in the data. As the developer stated, the fix does not clean up orphans created before it.
