What changed

The required-section guard in ConfigurationItemValidator.ValidateSectionTypeFile tested file presence only, so an empty upload discharged the requirement. It now also rejects the case where every attached file has Size <= 0 — reusing the existing CONFIGURATION_SECTION_FILES_REQUIRED code, scoped to required sections only.

What check 08 exposes

The data is safe; the buyer is not informed

The server now refuses the line item on the storefront’s own AddItem call. The storefront still enables “Add to cart” on a 0-byte file and surfaces nothing when the call is rejected — no toast, no inline message, clean console, empty cart. The buyer presses a live button and nothing happens, with no explanation.

The original report judged a storefront guard “cosmetic once the server rejects”. The data-integrity half of that is now closed and holds. The silent-failure half is what remains, and it is a separate, pre-existing vc-frontend defect — this fix did not cause it, it made it visible. It does not block VCST-6000 as a backend fix, and it should be filed on its own.
