# `/vc-test:qa-goal` Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Ship `/vc-test:qa-goal` — goal-driven testing of a non-trivial ticket with a journal, a checker, an OAuth helper and an independent judge — in the `vc-test` plugin.

**Architecture:** A command + skill drive the main agent through contract → research → criteria/strategy → test loop → draft verdict → judge → close, with three human stops. All state lives in one journal, `goal.json`, written only by `lib/goal.mjs`, which also enforces the stage gates. `lib/oauth-code.mjs` owns PKCE, the code redemption from the lane HAR and authenticated calls, so the agent never sees a token, a code or a password. `agents/goal-judge.md` re-derives the result read-only.

**Tech Stack:** Node.js ≥ 18 ES modules (no new dependencies; `fetch`, `node:crypto`, `node:fs`), Markdown prompt files, `node --test` for temporary tests.

**Spec:** `docs/superpowers/specs/2026-11-13-qa-goal-design.md`

## Global Constraints

- Plugin: `plugins/vc-test/` only. No file there may name a path under the repo's `.claude/` (`context:check` DOC-009).
- Each new command, agent and `SKILL.md` ≤ 19,000 chars (BUDGET-004); detail goes to supporting files.
- No new dependency in `plugins/vc-test/package.json`.
- Tests are **temporary**: `plugins/vc-test/lib/*.tmp.test.mjs`, run with `node --test`, **deleted before each commit**. No new committed test file (NO CODE ⇒ NO UNIT TEST; vc-test commits tests only for `knowledge-store.mjs` and `write-zones.mjs`).
- Working state root: `workDir(key, { env })` from `lib/paths.mjs` (`.vc-fix/vc-test/<KEY>/<env>/`). A run's folder is `<workDir>/goal/<runId>/`, `runId` = UTC `YYYYMMDDTHHMMSSZ`. *(Deviation from spec §5.5 "`{RUN_DIR}/goal/…`": `npm run run:use` exists only in this repository, so a client install cannot resolve `RUN_DIR`; `.vc-fix/**` is also always inside write zones.)*
- `artifacts.json` is **not** changed. *(Deviation from spec §5.1: write-zones already allows `.vc-fix/**` and `<store>/**` through `orchestrator.writes`; an artifact entry without a strategy row risks `plan-run.mjs`.)* `write-zones.mjs check` gets a run plan `{"waves":[]}` written by `goal.mjs init`.
- Never printed or stored by any script: an access/refresh/id token, an authorization code, a PKCE verifier, a password, a cookie. Tokens live only in `<runDir>/.tokens/`, deleted by `oauth-code.mjs purge` at close.
- Every string `goal.mjs` stores is scrubbed with `knowledgeSecretValues(outputRoot())` + `scrubValues()` from `lib/knowledge-store.mjs`; a value matching a JWT shape (`/eyJ[\w-]+\.eyJ[\w-]+\./`) is **refused** (exit 2), not scrubbed.
- Every script prints one JSON object on stdout. Exit codes: `0` done · `1` usage · `2` refused / gate failed (the JSON names every reason) · `3` could not run (I/O, network).
- `plugin.json` version `0.17.1` → `0.18.0`; tag `vc-test--v0.18.0` per `docs/release-process.md` §Step 1 + §Step 5a after merge.

## Review Focus

1. **A secret in journal input** (a token pasted into an evidence note, an `.env` password in a finding title) → `goal.mjs` refuses or scrubs it, and the file on disk never holds it. Test in Task 1.
2. **A lane HAR with several sign-ins** (two personas, an earlier run) → `oauth-code.mjs redeem` takes only the callback whose `state` it issued; no match ⇒ exit 2 "no callback for this persona's state", never another persona's code. Test in Task 3.
3. **The HAR not yet written** (the page was not closed) → exit 2 with "close the lane page so the HAR is written", not a crash. Test in Task 3.
4. **A PASS without evidence, or evidence outside the run folder** (`../../.env.local`) → `check --before verdict` fails naming the AC. Test in Task 2.
5. **A resumed run** (the session ended mid-run) → `goal.mjs init --key K` returns the newest unclosed run of that key and env instead of a new one; `--new` forces a new run. Test in Task 1.

### Task 2: The gates — `goal.mjs check` and `goal.mjs replay`

**Files:**
- Modify: `plugins/vc-test/lib/goal.mjs`
- Test (temporary): `plugins/vc-test/lib/goal-check.tmp.test.mjs`

**Interfaces:**
- Consumes: Task 1's `loadGoal`, the schema.
- Produces: export `checkGoal(goal, stage, { dir }) -> { ok: boolean, errors: string[], warnings: string[] }`; CLI `check --dir <d> --before strategy|write|verdict|close` (exit 0 ok · 2 errors); CLI `replay --dir <d> --id RP-n` → `{ id, status, expectStatus, match }` (GET/HEAD only, no `Authorization` header, 20 s timeout).

**Rules (from spec §5.2, exact):**
- `strategy`: `contract.approvedAt` set; `acs.length ≥ 1`; every AC has `source`; every AC id appears in some `strategy[].acs`.
- `write` (CLI adds `--what <label>`, e.g. `bug:F-1`, `comment`): a checkpoint `{ stop: "S3", decision: "approved", note: <label> }` exists. *(The command records one S3 per write, its `--note` the same label.)*
- `verdict`: no AC `open`; every `GAP` has `gapReason`; every `PASS`/`FAIL`/`PARTIAL` has ≥ 1 evidence; every evidence `path` resolves inside `dir`; every finding has `severity` and ≥ 1 evidence; a finding of `Medium` or worse has `reproduced ≥ 2`; a checkpoint `S2 approved` exists; `cost` present.
- `close`: `judge.verdict` set; `closed.writeZones` and `closed.teardown` set.
- Warning (not an error) at any stage: `cost.inputTotal` over 80 % of `budget.tokens`, or `cost.wallMin` over 80 % of `budget.wallMin`; an error when either is over 100 % at `strategy` and `verdict`. (`cost` is what `run-cost.mjs --key` wrote, stored by `goal.mjs cost --file`.)

### Task 3: OAuth helper — `oauth-code.mjs`

**Files:**
- Create: `plugins/vc-test/lib/oauth-code.mjs`
- Test (temporary): `plugins/vc-test/lib/oauth-code.tmp.test.mjs` (synthetic HAR files + a local `http.createServer` stub for discovery, token and MCP endpoints)

**Interfaces:**
- Produces (CLI, all with `--dir <runDir> --persona <name>`; persona matches `/^[a-z0-9-]{1,32}$/`):
  - `start --issuer <url> --client <id> --redirect <uri> [--resource <uri>] [--scope "openid offline_access"]` → reads `<issuer>/.well-known/openid-configuration`; stores `{ verifier, state, client, redirect, resource, tokenEndpoint }` in `<dir>/.tokens/<persona>.pkce.json`; prints `{ url }` (S256 only).
  - `redeem --har <path>` → finds the HAR entry whose request URL starts with `redirect` and whose `state` equals the stored one (or a response `Location` header to it); posts `authorization_code` + verifier; writes `<dir>/.tokens/<persona>.json`; prints `{ persona, aud, iss, sub, name, roles, permissions, expiresIn, hasRefresh }`. Deletes the `.pkce.json`.
  - `refresh` → rotates using the stored refresh token; prints the same claim summary.
  - `mcp --url <mcp url> --method <jsonrpc method> [--params-file <json>]` → `initialize` + `notifications/initialized` + the call (Streamable HTTP, `Mcp-Session-Id`); prints `{ status, result }` with `result` trimmed to 4,000 chars and every stored token value scrubbed.
  - `http --method GET|POST|DELETE --url <url> [--body-file <json>]` → `{ status, body }` (trimmed, scrubbed).
  - `purge` → removes `<dir>/.tokens/` → `{ purged: n }`.
- Never reads any HAR entry other than the matching callback; never prints the code, verifier or token.
