# `/qa-docs` Implementation Plan

> **Superseded in part (2026-10-30):** this plan says "status Tested" throughout. The gate is now **Tested or Done**,
> with an existing-documentation check first — see the spec's *Amendment 2026-10-30* and `.claude/skills/qa-docs/SKILL.md`.

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** One skill, `/qa-docs`, writes one three-part document (What's new · How to set it up · How it works) for a ticket in status Tested, posts it as one Jira comment, and builds a ≤30 s Motion film that a person exports and attaches; every older documentation path is removed.

**Architecture:** A project skill folder `.claude/skills/qa-docs/` holds the flow (`SKILL.md`) and its supporting files (template, rules, media, release aggregate, film helper). `/qa-test` FULL 5-docs calls it; `/ba-analyze`, `ba-doc-writer`, `virto-doc-style.md` and `reports-policy.md` §5.2a lose their documentation parts and point at it.

**Tech Stack:** Markdown prompts (Claude Code skills/commands/agents), one JSON template, one browser-side JS module for the Motion artifact. No repository code changes ⇒ no unit tests (`CLAUDE.md` NO CODE ⇒ NO UNIT TEST); the gates are the tests.

**Spec:** `docs/superpowers/specs/2026-10-30-qa-docs-design.md` — read it first; this plan argues from it.

## Global Constraints

- Every `SKILL.md`, command and agent body ≤ 19,000 chars (BUDGET-004); a file in `scripts/maintenance/.prompt-size-baseline.json` may only shrink.
- Gate set (the `offline` job of `.github/workflows/gates.yml`), all must exit 0: `npm run context:check`, `npm run knowledge:index:check`, `npm run docs:index:check`, `npm run qa-test:doclint`, `npm run vc-test:design:check`, `npm run kb:stands`, `npm run suites:lint`, `npm run td:validate`, `npm run td:validate:all`, `npm run bl:lint`, `npm run ecl:lint`, `npm run bl:convert:check`, `npm run suites:executability:check`.
- Generated indexes are regenerated, never hand-edited: `npm run docs:index` (skills README), `npm run knowledge:index` (knowledge README).
- New and restructured components follow `.claude/knowledge/agents/authoring-standard.md` (frontmatter, cite-don't-restate §3–§4, kb read/write steps §5.4 wording).
- Gate for writing documentation: the ticket's tracker status is **Tested**, read live; otherwise refusal `not-tested`.
- Film length ≤ 30 s; Claude never creates a video file; the person exports MP4 from the film page.
- Browser work only on a Playwright lane (`.claude/rules/vc-browser.md`); passwords typed by lane secret name.
- No commit of screenshots, GIFs, video or HAR (`.claude/rules/reports.md` §9).
- Plugins: only the one-line pointer in `plugins/vc-test/commands/qa-ticket.md` changes; no version bump in this work. `plugins/vc-fix/**` and `plugins/vc-test/skills/qa-design/visual-axis.md` are not edited (follow-ups).

## Review Focus

1. **A ticket already past Tested (Done, Closed) when `/qa-docs` is run.** The design gates on Tested exactly; a reviewer should confirm `SKILL.md` refuses it with `not-tested` and says why, not silently writes. Owning task: Task 2 (grep in Step 4).
2. **The stand was redeployed between the test run and the capture walk.** Expected: stop and ask, no screenshots from a different build. Owning task: Task 3 (grep in Step 4).
3. **`/qa-docs <TICKET> --video` run before the person attached the MP4.** Expected: it reports the attachment is missing and does not amend the comment. Owning task: Task 3.
4. **A `/vc-test:qa-ticket` run (no `summary.json`, no probed versions).** Expected: the skill reads `verdict.json`, probes `/api/platform/modules` before capture, and the footer says versions were read at capture time. Owning task: Task 2.
5. **The `/qa-test` result comment's `Release note` line after the fragment file disappears.** Expected: `none — see the documentation comment`, not `none — not resolved`. Owning task: Task 5.
