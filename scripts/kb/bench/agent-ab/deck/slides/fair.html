How we keep it fair

One difference, nothing shared

A clean desk every run

A new empty folder with a random name, wiped after the run.

No shared memory

No chat history, no project notes, no skills. Our repo is out of reach.

Only one difference

Access to the base, plus one line on when to use it. Same model, task and test site.

One at a time, taking turns

Runs never meet on the shared test site, and who goes first alternates.

The same grader for both

A separate model checks each answer against a written rubric. A sample is checked by hand.

A leak voids the run

If an agent touches our repo, another run, or the base when it should not, the run is discarded.

Not git branches: each run is a separate process in its own throwaway folder, outside the repository.

People will ask whether the agent without the base secretly got the answer anyway. Six rules prevent it. Each run gets a fresh empty folder with a random name that is deleted afterwards, so nothing one agent writes can be found by the next. No chat history, project notes, memory or skills are loaded, and the run cannot see our repository, which contains much of the same knowledge. The only difference between the two setups is access to the base and one instruction about when to use it. Runs go one at a time, because they share the live test site: two agents creating promotions in the same store would spoil each other's results. Who goes first alternates. A separate model grades every answer against the same written rubric, and I check a sample by hand. Finally, every tool call is scanned; if an agent touches the repo, another run, or the base when it is not supposed to, the run is thrown out.
