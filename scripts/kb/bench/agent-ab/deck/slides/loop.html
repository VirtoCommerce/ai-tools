Dashed line: every confirmation, dispute and new fact flows back into the base. Every "not found" is logged and becomes its to-do list.

This is the whole mechanism. 1) While working, the agent hits a question about how the platform behaves, for example whether two promotions stack. 2) Before asserting anything it asks the base, one quick lookup; the question names the page, endpoint or GraphQL operation, which is what the search is strongest on. 3) Known: the agent gets the fact with a trust level and where it was seen, uses it, and after checking it on its own run it confirms it (trust grows) or disputes it (a human decides; nothing is deleted automatically). 4) Not known: the agent finds out live, in the browser, through the API or in source code, and writes the fact down as one short entry. Before anything is published, a gate checks for secrets and duplicates. 5) The next agent, in any team or customer project, gets it in one lookup. Questions the base could not answer are logged; that list is the to-do list for the base.
