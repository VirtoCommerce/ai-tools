The problem

Every agent starts from zero

It rediscovers the same quirks

Clicks, API calls and tokens spent on a question someone already answered last week.

It guesses, and guesses wrong

A plausible guess becomes a wrong test assertion or a bug that is not a bug.

What it learned is lost

The session ends, and the finding ends with it.

A real example

Two "stackable" promotions on one cart: 15% off and $50 off.

Only the bigger one applies.

The "exclusive" flag does not decide it; a store setting does. Three separate agent runs were needed to pin it down. Now it is one lookup.

Example: knowledge-base entry KB-5ADBFB34 · well attested, 6 confirmations

Agents are smart but have no memory between sessions. Three costs: they spend time and tokens rediscovering quirks; when they do not check, they guess, and a plausible guess is often wrong, which turns into wrong assertions or false bug reports; and whatever one session learns disappears when it ends. The example on the right is real: with two promotions active, people and models expect them to stack. The platform keeps only the most valuable one, because of the store's CombinePolicy setting, and isExclusive is irrelevant. It took three independent runs to establish. Today any agent gets it in one lookup.
