Why it is safe to rely on

Four rules the base keeps

Evidence, not opinion

Only what an agent saw on a live system goes in, with where and when it was seen.

Agents flag, humans decide

Nothing is deleted automatically. A dispute marks the fact for a person to review.

Public, so nothing private

A gate blocks secrets before publishing. No passwords, tokens or customer names.

Not sure? It says so

It answers alone only when it is confident. Otherwise it shows the close candidates and the agent checks.

The base is a public GitHub repository (VirtoCommerce/vc-knowledge): every change is a reviewable commit. Opt-out: one setting.

Four rules make it safe to rely on. Evidence, not opinion: an entry records what an agent actually observed on a live deployment, with the environment, version and time. Agents flag, humans decide: confirm and dispute are the only things an agent can do to an existing fact; a dispute never deletes anything. Public, so nothing private: the base is a public repo shared across teams and customers, so a secret gate runs before every publish and client-specific data is not allowed in. Not sure, it says so: the base gives a confident answer on its own only above a calibrated threshold; otherwise it returns a few close candidates and the agent decides by reading them, or it says nothing is recorded. Every change is a git commit, so it is auditable, and a machine can opt out with one setting.
