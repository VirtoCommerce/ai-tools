# Spec practice — locators, waits, math, collectors, cleanup

Read from `/qa-test-automation` step 4 while writing. Worked examples (by path — read, do not paste):
`regression/suites/Frontend/cart/028-cart-core/CART-001.spec.ts`, `CART-006.spec.ts`, `CART-007.spec.ts`;
helpers `regression/lib/cart.ts`, `regression/lib/fixtures.ts`, `regression/lib/data.ts`.

## Locators — in this order

1. **Role + accessible name**: `getByRole("button", { name: "Increase quantity" })`, `getByRole("spinbutton", { name: "Product quantity" })`.
2. **Label / text**: `getByLabel`, `getByText` (exact where the copy is stable).
3. **Generated storefront test ids**: `testIdSelector("<id>")` from `scripts/lib/storefront-selectors.generated.ts` (imported with a `.js` extension, as the pilots do)
   — never type the `data-test-id` string; the surface is regenerated by `selectors:sync` and checked by
   `selectors:check` ([`../../knowledge/execution/regression-selectors.md`](../../knowledge/execution/regression-selectors.md)).
4. **A UI-kit class** only when nothing above exists (the pilots use `.vc-line-item`, which carries no test id),
   with a one-line comment saying why.
5. Never: nth-child chains, generated hashes, coordinates, XPath by position. Scope a locator to its section
   first (`products.locator(...)`), then to the row.

## Assertions and waits

- **Web-first `expect`** (`toHaveText`, `toHaveValue`, `toBeVisible`, `toHaveCount`) — they retry. For a value
  that is not an element property (a server cart, a collected request) use `expect.poll(() => …).toBe(…)`.
- **No `waitForTimeout`, no `sleep`.** Wait on the thing you need: a locator (`waitFor`), a response, or a poll.
- No `networkidle` as a synchroniser in a case body (the session fixture uses it once, for the sign-in check).
- A plain `if (…) throw new Error(...)` guards a **precondition** (BLOCKED); `expect` states the **check** (FAIL).

## `[MATH]` is computed from page values

A `[MATH]` assertion computes the expectation **from what the page shows**, never from a number you saw once:
read the unit price with `money(text)`, multiply, compare to the displayed total with
`formatMoney(...)` (`regression/lib/cart.ts`). A hardcoded `"$24.00"` is a transcribed constant that passes
exactly once. Sum a column by reading every line total, not by assuming the line count. Pilot: `CART-006.spec.ts` (line total and subtotal).

## Console and network collectors

- Attach the collector **before** the first navigation: `const traffic = watchCartTraffic(page)`; it records
  console errors, HTTP 4xx/5xx and cart mutations (`regression/lib/cart.ts`).
- `[CONSOLE]` ⇒ `expect(traffic.consoleErrors).toEqual([])`; `[NETWORK]` ⇒ `expect(traffic.httpErrors).toEqual([])`.
- `[API]` / `[GQL]` checks on what the storefront sent: read it from the collector, not from a re-issued call.
  The row may name an operation the storefront does not use; assert on the mutation that carried the effect and
  say so in a comment (observed names go to the base, `kb_capture`), as `CART-006.spec.ts` does.
- Slice by index (`traffic.cartMutations.slice(before)`) so earlier traffic is not attributed to this step.
- **Evidence is not yours to capture.** Playwright already keeps a screenshot and a trace on failure for every
  context made in a test, including `signedInAs` pages, and a HAR for every spec. Never add a manual failure
  screenshot, never name an output path ([`../../rules/test-data.md`](../../rules/test-data.md) THIRD RULE).

## Cleanup through API

Mirror the row's `Cleanup`: in `test.afterEach`, `await resetCart(await apiAs(ROLE))` or the entity-specific
API delete — never by clicking through the UI, and written so it runs even when the test failed. Created
entities carry the `AGENT-TEST-` prefix.

## Running notes you will meet

- Sign-in on vcst is **OTP-first**; it is handled inside `save-storage-state.ts` / the fixture. A spec never signs in.
- A cached storageState goes **stale after roughly 30-80 minutes**; `signedInAs` heals it itself. Sessions are
  cached per env and role (`test-results/auth/<TEST_ENV>/<role>.json`); a cached file that is unreadable or no
  longer signs in is recreated once. Only a session made just now that still does not sign in throws
  `signedInAs(<role>): session not signed in` (BLOCKED): the account or the sign-in form is broken, not the cache.
- The shared `ADMIN_DEFAULT` account **locks for 10-20 minutes** if full runner runs follow each other back to back.
- Project flag is written `--project=script` / `--project=runner` (no space). `npm run specs:run` / `specs:runner` carry it.
- `-g` matches against "project file describe title": `-g "CART-001:"`; for a runner suite `npm run specs:runner -- -g " 050a "` (spaces, no `^`).

## Anti-flake checklist (tick before the D9 run)

- [ ] Data only through `env` / `td` / `discover` / `random`; no literal URL, GUID, e-mail, SKU, price.
- [ ] State seeded through `apiAs` **before** the page opens; precondition guard throws a plain `Error`.
- [ ] Every wait is on an element, a response or `expect.poll`; zero `waitForTimeout`.
- [ ] Locators by role / label / text / generated test id; none by position or class hash.
- [ ] `[MATH]` computed from values read off the page.
- [ ] Collector attached before the first `goto`; console and network asserted last.
- [ ] `afterEach` cleanup through API; no manual screenshot or evidence path.
- [ ] Not both `page` and `signedInAs` in one test.
- [ ] Ran the new spec twice in a row (second run proves the cleanup and the seed are repeatable).
- [ ] `suites:lint` and `td:validate` clean.
